# 07 论文与答辩问答

## 你需要先知道

答辩重点不是背完所有数字，而是区分“实现做了什么、证据说明什么、还缺什么”。
auto没有达到最佳点、setup很重，都是应当主动说明的研究结果。

## 核心原理

讲解顺序为：Q5语义、Arrow输入、CPU物理计划、CUDA三模式、resident生命周期、
hybrid fixed/auto、实验协议、结果、限制。所有数字来自claim ledger的VERIFIED
或REJECTED条目。V5 cold只用于说明为什么复用计划和buffer会改变排名。

## 自己检查

试着回答：“hybrid请求最快，为什么不直接说项目成功实现了GPU加速？”

**检查答案：** fixed hybrid的稳态request在两个规模都比专用CPU低，但setup更高，
少量请求时仍可能更慢；只测了固定Q5、两个规模和一台GPU，不能推广为普遍结论。

## 老师可能追问

你个人能接手什么？能解释Q5每个条件，定位CPU/GPU/hybrid入口，生成Arrow数据，
运行tiny、CTest、正式matrix和审计，区分四种计时口径，并追到论文数字的CSV行。

## 一分钟复述

项目完成了固定Q5的Arrow CPU--GPU对比。所有V7请求正确；copy和managed接近，
mapped远程访问很慢；fixed hybrid稳态请求有收益，但setup高；auto会调比例，却
没有达到离线最优。限制是固定查询、两个规模、单机和无并发。
