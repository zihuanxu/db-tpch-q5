# 07 论文与答辩问答

## 你需要先知道

答辩重点不是背所有数字，而是能区分“代码做了什么、证据支持什么、还有什么
没做”。负结果也可以是有效研究结果。

## 核心原理

讲解顺序固定为：Q5 语义 -> Arrow 输入 -> specialized/Acero -> CUDA 三模式 ->
hybrid -> 实验协议 -> 结果 -> 限制。数字只从 claim ledger 的 VERIFIED 或
REJECTED 条目取。遇到“为什么没加速”，先承认结果，再解释重复计划、GPU staging、
冷启动和 SF1 规模，不能把原因说成已经被 profiler 证明。

## 自己检查

试着回答：“既然 CPU 最快，这个 CPU--GPU 项目是不是失败了？”

**检查答案：** 不是。项目实现并验证了三种内存方式和混合执行，找到了数据移动
位置和冷进程开销的差别，也得到可复现的负结果；但不能声称完成了普遍 GPU 优化。

## 老师可能追问

你个人现在能接手什么？能修改 Q5 参数与计划，定位各后端入口，重新生成 Arrow
数据，跑 tiny/CTest/正式矩阵，审计证据，并解释论文每个主要数字的来源。

## 一分钟复述

这个项目完成了固定 Q5 的 Arrow CPU--GPU 对比。正确性全部通过，copy 优于
managed/mapped，hybrid 没有超过专用 CPU。结论受 SF1、冷进程和固定查询限制。
