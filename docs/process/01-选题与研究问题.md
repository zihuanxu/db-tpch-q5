# 01 选题与研究问题

**日期范围：** 2026-07-01 至 2026-07-14

## 目标

围绕 TPC-H Q5 做一个固定查询执行器，在同一 Arrow 输入上比较专用 CPU、
Arrow Acero、三种 CUDA 内存方式、cuDF 和 CPU--GPU 混合执行。项目研究的是
查询物理计划和数据移动，不是实现完整 DBMS。

## 活动与证据

| 问题 | 初始预期 | 当前状态 | 证据 |
| --- | --- | --- | --- |
| RQ1：不同后端能否保持精确 Q5 语义 | 能 | 已验证 | `docs/artifacts/v5_sf1/correctness.json` |
| RQ2：专用 CPU 与 Acero 有何差别 | 专用计划更快 | 已验证 | `docs/artifacts/v5_sf1/summary.csv` |
| RQ3：copy、managed、mapped 如何取舍 | managed 可能更方便且接近 copy | 部分否定 | `docs/research/CLAIM_LEDGER.md` C004-C005 |
| RQ4：cuDF 算子库的代价在哪里 | 查询代码短，但冷启动重 | 已验证 | C006 |
| RQ5：混合执行能否加速 | 可能超过纯 CPU | 已否定 | C007-C008 |

## 未解决问题

没有 SF10、常驻查询和并发查询证据，因此还不知道规模增大后是否出现交叉点。

只把 SF1 上可审计的结论写进论文，把 SF10 和 resident 保留为后续工作。
