# 02 系统设计方案

**日期范围：** 2026-07-13 至 2026-07-14

## 目标

用一份 canonical Arrow IPC 数据集支撑所有正式后端，并让 CPU、GPU 和混合
结果使用同一个 `revenue_1e4` 定点数契约。

## 活动与证据

| 层次 | 方案 | 代码/文档 |
| --- | --- | --- |
| 数据 | 六表只保留 Q5 必需列，写 Arrow IPC 与 manifest | `scripts/prepare_arrow_dataset.py` |
| CPU | 稠密键直接索引的专用计划；Acero 关系算子计划 | `src/cpu/` |
| GPU | 同一 kernel，对比 copy、managed、mapped | `src/cuda/q5_arrow_cuda.cu` |
| 混合 | 按 batch 分割 lineitem，CPU/GPU 并发，精确归并 | `src/hybrid/q5_hybrid.cpp` |
| 算子库 | cuDF merge/filter/groupby/sort | `baselines/cudf_q5.py` |
| 正确性 | 项目 hash 加官方五行 oracle | `scripts/verify_q5_oracle.py` |

Arrow 统一的是输入和 schema，不意味着不同后端的内部准备工作相同。专用路径
会建立直接索引，cuDF 需要转换为 DataFrame，GPU 还要准备可访问的列缓冲区。

## 未解决问题

CPU 和 GPU 在混合路径中仍有重复准备；GPU 也没有执行完整六表连接。

## 下一步决定

课程交付保留当前范围，优化优先级放在计划和缓冲区复用，而不是新增 SQL parser。
