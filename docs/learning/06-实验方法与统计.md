# 06 实验方法与统计

## 你需要先知道

性能表不是“跑一次抄一个数字”。正式证据必须能说明配置、重复、失败、正确性
和统计方法。

## 核心原理

每组配置先 3 次 warmup，再 10 次 measured cold process。中位数抗偶发抖动，
p95 表示较慢尾部，样本标准差说明波动。`query_total_ms` 观察后端查询阶段，
`process_elapsed_ms` 还包含进程启动、装载和 Python/Conda 导入。cuDF 的
`load_ms` 单独记录 Arrow 加载和转换。结果 hash 用于快速发现后端差异，官方
oracle 再检查五行金额，二者缺一不可。

## 代码入口

- 正式矩阵：`experiments/v5_formal_sf1.yml`
- 运行记录 schema：`scripts/benchmark_schema.py`
- 统计：`scripts/summarize_run_records.py`
- 审计：`scripts/evidence_bundle.py`

## 自己检查

为什么 cuDF 查询 116.427 ms，但进程时间 3682.381 ms？

**检查答案：** 每个 cold sample 都启动 Conda/Python、导入库、读取和转换六表，
这些不全在 query 字段里。两列回答不同问题。

## 老师可能追问

失败是否应该从统计里删除？成功样本的性能统计不混入失败时长，但失败记录必须
保留并单独计数，否则会形成只报告成功结果的偏差。

## 一分钟复述

正式矩阵有 19 组配置、190 个测量样本和 57 个预热，全部通过 oracle。论文的
数字由脚本从 raw.csv 重算，不手工挑最好一次。
