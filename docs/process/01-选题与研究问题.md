# 01 选题与研究问题

**日期范围：** 2026-07-01 至 2026-07-14

## 目标

围绕 TPC-H Q5 做一个固定查询执行器，在同一 Arrow 输入上比较专用 CPU、
Arrow Acero、三种 CUDA 内存方式、cuDF 和 CPU--GPU 混合执行。项目研究的是
查询物理计划和数据移动，不是实现完整 DBMS。

## 活动与证据

| 问题 | 初始预期 | 当前状态 | 证据 |
| --- | --- | --- | --- |
| RQ1：不同后端能否保持精确 Q5 语义 | 能 | SF1/SF10 已验证 | `v7_sf1_resident/correctness.json`、`v7_sf10_resident/correctness.json` |
| RQ2：专用 CPU 与 Acero 有何差别 | 专用计划更快 | 已验证 | C016、C021 |
| RQ3：copy、managed、mapped 如何取舍 | managed 可能接近 copy | 已验证但无固定赢家 | C013、C018 与 profiler |
| RQ4：cuDF 算子库的代价在哪里 | 通用算子有额外代价 | 已验证 | C016、C021 |
| RQ5：混合执行能否加速 | resident 下可能超过 CPU | fixed 已支持 | C014、C019 |
| RQ6：自动比例能否替代扫描 | 能接近最优 | 被部分否定 | C015、C020 |

## 未解决问题

只有 SF1/SF10 两个规模点，仍没有多查询并发、NUMA 和多 GPU 型号证据，无法
建立普遍规模模型。auto 在 SF1 的 regret 较大。

## 下一步决定

论文同时报告 SF1/SF10 resident、setup 摊销和 profiler 机制证据，但把并发、
多硬件和通用查询保留为后续工作。
