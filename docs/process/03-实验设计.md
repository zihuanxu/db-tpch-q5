# 03 实验设计

**日期范围：** 2026-07-13 至 2026-07-14

## 目标

让每条性能结论都能从原始记录重算，分清一次setup与重复request，并且失败不会
被静默删除。

## 活动与证据

| 项目 | V7 正式口径 |
| --- | --- |
| 数据 | TPC-H SF1/SF10 Arrow，ASIA，1994年 |
| 配置 | 每规模18组：CPU 3、Acero 3、CUDA 3、fixed hybrid 7、auto 1、cuDF 1 |
| 生命周期 | 每配置建立一次resident session |
| 重复 | 3次warmup + 10次measured request |
| 计时 | setup、request p50/p95、1/10/100次摊销 |
| 正确性 | 每个request精确hash且逐行通过oracle |
| 失败 | 保留进程、schema、hash、GPU或collector失败 |
| profiler | 10组单request NSYS/NCU，与普通性能分开 |

矩阵在`experiments/v7_formal_sf1.yml`和`v7_formal_sf10.yml`；runner、schema、
统计和审计分别在`run_v7_benchmarks.py`、`v7_benchmark_schema.py`、
`summarize_v7_records.py`和`v7_evidence_bundle.py`。

## 未解决问题

setup每组只建立一次，没有形成setup分布；没有多查询并发、NUMA绑定和GPU峰值
显存正式矩阵。profiler重放会扰动统一内存时间。

## 下一步决定

论文将cold、setup、request、profiler四种口径分开；profile只解释机制，不进入
普通延迟排名。
